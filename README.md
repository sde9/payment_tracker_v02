# Уроки и оплаты

Учёт предоплаченных занятий для частного преподавателя английского. Ученики платят вперёд пакетами по 4, 5 или 10 уроков, приложение держит баланс в уроках и в рублях, списывает проведённые занятия и подсказывает, кому пора напомнить об оплате.

Одна HTML-страница без сборки, без сервера и без внешних запросов, кроме шрифтов Google Fonts.

## Что умеет

- Карточка ученика: имя, своя ставка, контакт, заметка, текущий баланс
- Оплата пакетом 4 / 5 / 10 или любым числом уроков, сумма считается по ставке
- Три исхода занятия: провёл, отмена со списанием урока, отмена без списания
- Отрицательный баланс с суммой долга, следующая оплата гасит его сама
- Блок «Пора напомнить об оплате» при остатке ниже порога, порог настраивается
- Готовый текст сообщения ученику, два шаблона: остаток заканчивается и есть долг
- Отметка нескольких занятий за день одним экраном, дата любая
- История операций по каждому ученику с отменой последней записи
- Доход и число уроков за месяц, с переходом по прошлым месяцам
- Архив учеников
- Резервная копия в браузере и выгрузка в файл JSON

Правило шести часов применяется вручную. При отмене приложение спрашивает, списывать урок или нет: время начала занятия не хранится, зато остаётся место для исключений.

## Три способа запустить

**Автономная страница.** Откройте `index.html` в браузере. Работает без сети, данные лежат в `localStorage` этого браузера.

**Vercel.** Проект подключается к репозиторию как есть, настройки сборки в `vercel.json`. Каждый push в `main` выкатывает новую версию. С подключённым Redis данные хранятся на сервере и видны с любого устройства.

**Артефакт claude.ai.** Опубликуйте `src/app.html` через Claude с возможностями `artifact` и `downloads`. Страница сама хранит состояние на сервере claude.ai.

## Хранение данных

Страница выбирает хранилище при загрузке, в таком порядке:

| Режим | Когда включается | Где лежат данные |
|---|---|---|
| `artifact` | доступен рантайм claude.ai | документ артефакта, синхронизируется между устройствами |
| `server` | отвечает `/api/state` | Redis, один ключ со снимком целиком |
| `local` | всё остальное | `localStorage` браузера |

В любом режиме снимок дублируется в `localStorage`, поэтому обрыв сети не теряет то, что уже на экране. Индикатор в шапке показывает текущий режим и момент записи.

Снимок отправляется на сервер через 0,7 секунды после последнего изменения, а не на каждый клик. При закрытии вкладки несохранённое уходит через `sendBeacon`. Обработчик отклоняет снимок без массива `students`, чтобы битый запрос не затёр реальные данные, и перед каждой записью кладёт предыдущую версию в `uroki:state:prev`.

### Как включить серверное хранение на Vercel

1. В проекте на Vercel откройте **Storage** и через Marketplace добавьте **Upstash Redis**, бесплатного тарифа хватает с запасом.
2. Подключите созданный ресурс к проекту. Интеграция сама пропишет переменные окружения, обработчик понимает варианты `KV_REST_API_URL` / `KV_REST_API_TOKEN` и `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`.
3. Передеплойте проект. Индикатор в шапке должен смениться на «сохранено на сервере».
4. Закройте страницу от посторонних: **Settings → Deployment Protection → Vercel Authentication**. Без этого любой, кто узнает адрес, увидит и сможет изменить балансы.

Пока Redis не подключён, `/api/state` отвечает `503`, а страница честно переходит в режим `local` и пишет в браузер.

## Структура

```
src/app.html         источник: фрагмент страницы для артефакта claude.ai
build.js             оборачивает фрагмент в полноценный HTML
index.html           собранная страница, лежит в репозитории
public/index.html    та же страница для Vercel, генерируется при сборке
api/state.js         чтение и запись снимка в Redis
vercel.json          команда сборки и каталог выдачи
push.sh              первая отправка на GitHub одной командой
test/app.test.js     сценарии учёта в Chromium
test/server.test.js  серверное хранение целиком, с поддельным Redis
docs/requirements.md требования и границы проекта
```

`src/app.html` не содержит `doctype`, `html`, `head` и `body`: при публикации артефакта claude.ai добавляет их сам. `build.js` дописывает недостающее для автономной версии.

## Сборка и тесты

```bash
npm install
npm run build   # src/app.html -> index.html и public/index.html
npm test        # сборка и прогон сценариев
```

`test/app.test.js` проверяет учёт: стартовые балансы, оплату пакетом, проведённое занятие, отмену со списанием и без, уход в минус и погашение долга, смену ставки с пересчётом сумм, порог напоминания, отмену последней записи, добавление ученика, отметку дня, месячную сводку, резервную копию, обе темы и отсутствие горизонтальной прокрутки на телефоне.

`test/server.test.js` поднимает настоящий обработчик `api/state.js` поверх поддельного Upstash и проверяет полный круг: заливку начального состояния, запись изменений, чтение с чистого браузера как со второго устройства, отклонение битого снимка и поведение при обрыве сети.

Playwright нужен только для тестов. Vercel его не ставит: `installCommand` в `vercel.json` отключён, сборке хватает одного `node build.js`.

## Как устроено хранение

Состояние живёт в самой разметке: баланс в тексте, тип операции и суммы в атрибутах `data-*`. Скрипт ничего не рисует при загрузке, кроме вычисляемых блоков внутри `<artifact-local>`, месячной сводки и списка напоминаний. Благодаря этому в режиме артефакта каждое действие пользователя попадает в документ и доживает до следующего открытия, а в автономном режиме то же состояние снимается в `localStorage` и восстанавливается при загрузке.
